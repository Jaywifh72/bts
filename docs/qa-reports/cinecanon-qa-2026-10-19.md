## P1 — Degraded

### P1-1 — Organization JSON-LD logo points at non-existent `/icon-512.png`

**File:** `apps/web/app/page.tsx` line 133

The homepage `WebSite` JSON-LD block emits an `Organization.logo` URL of `siteUrl() + '/icon-512.png'`. No such file exists in `public/` and no Next.js route handler serves that path. The app exposes `/icon.svg` (favicon), `/apple-icon.png` (180×180 generated by `apple-icon.tsx`), and a root OG image at `/opengraph-image`, but nothing at `/icon-512.png`. A live 404 on this URL signals an invalid Organization logo to Google's Knowledge Graph and schema validators.

The fix is either to add a `public/icon-512.png` asset or to point the `logo` field at an existing endpoint such as `/opengraph-image` or to use the apple-icon URL with `absoluteUrl('/apple-icon.png')`.

### P1-4 — `alt=""` on content images across multiple pages

**Files:** 7 occurrences found

Film poster thumbnails in filmography grids are served with `alt=""`, meaning they are invisible to screen readers and excluded from Google Image Search indexing:

| File | Line | Context |
|---|---|---|
| `app/crew/[slug]/page.tsx` | 848 | 56px film poster in "Known for" filmography grid |
| `app/vfx/[slug]/page.tsx` | 172 | 64px film poster in VFX house filmography |
| `app/gear/[manufacturer]/[series]/page.tsx` | 268 | 36px film poster in gear series filmography |
| `app/ask/page.tsx` | 254 | Film poster in search result card |
| `app/format/[slug]/page.tsx` | 96 | Film poster thumbnail in format filmography |
| `app/gear/compare/page.tsx` | 196 | Film poster in comparison shared-productions panel |
| `app/account/page.tsx` | 30 | User avatar photo (OAuth provider image) |

The account page avatar is the most clear-cut case — it displays the logged-in user's face and should carry `alt={session.user.name ?? 'Profile photo'}`. The poster thumbnails adjacent to visible title text are technically borderline per WCAG (since the title is in adjacent text), but Google's image indexing guidelines recommend descriptive alt for all content images. Setting `alt` to the film title on these thumbnails is the correct fix.

### P1-5 — `tools/loadout` page has two `<h1>` elements in rendered HTML

**File:** `apps/web/app/tools/loadout/page.tsx` lines 81 and 91

The loadout page renders two h1 tags: one for screen display (`className="mt-1 font-serif text-3xl text-zinc-50"`) and one inside a print-only block (`className="font-serif text-2xl"` inside `header className="mb-6 hidden print:block"`). Although the print header is hidden via `display:none` on screen, both h1 elements are present in the DOM and in the server-rendered HTML. Search engines crawling the static HTML will see two `<h1>` tags, which degrades heading hierarchy signals. The print-only header should use an `<h2>` or the print content should be rendered outside the primary document flow.

## P2 — Polish

### P2-1 — 31 public content pages lack a canonical URL in their metadata

A systematic check of all non-admin `page.tsx` files with `export metadata` or `generateMetadata` shows 31 pages that emit no `alternates.canonical`. These rely on Next.js/browser default resolution, which may not match the URL Google indexes (especially with trailing-slash normalization). The most impactful missing canonicals:

- All gear detail pages: `app/gear/[manufacturer]/page.tsx`, `app/gear/[manufacturer]/[series]/page.tsx`, `app/gear/[manufacturer]/[series]/[item]/page.tsx`, `app/gear/page.tsx`
- All stunt sub-pages: `app/stunts/page.tsx`, `app/stunts/people/page.tsx`, `app/stunts/companies/[slug]/page.tsx`, `app/stunts/sequences/page.tsx`, `app/stunts/sequences/[productionSlug]/[sequenceSlug]/page.tsx`, `app/stunts/rigging/[slug]/page.tsx`, `app/stunts/lineage/page.tsx`
- Format pages: `app/format/page.tsx`, `app/format/[slug]/page.tsx`
- Tools pages (older tools): `app/tools/page.tsx`, `app/tools/frame-lines/page.tsx`, `app/tools/coverage/page.tsx`, `app/tools/cdl/page.tsx`
- `app/films/[slug]/scenes/[sceneSlug]/page.tsx`, `app/societies/page.tsx`, `app/references/[id]/page.tsx`

Note: utility/auth pages (`/account`, `/bookmarks`, `/signin`, `/films/[slug]/loadout`) have `robots: { index: false }` so canonical is less critical there.

### P2-3 — `/lookbook` exposes an unbuilt feature with no noindex treatment

**File:** `apps/web/app/lookbook/page.tsx`

The lookbook page is publicly accessible at `/lookbook`, is linked from the footer, and has full SEO metadata with a canonical URL, but its eyebrow text reads "Visual search · upload coming soon" and the main prose describes the image-upload feature as "in development". The SigLIP encoder backend does not exist. The page renders a palette browser as a fallback that is already available at `/shots`.

Options: either add `robots: { index: false }` until the feature ships, or remove the "coming soon" eyebrow so the page can be properly indexed as a palette-search tool that is actually available today.

### P2-4 — Root-layout meta description is 157 characters (2 over the 155 recommended cap)

**File:** `apps/web/app/layout.tsx` line 20

```
description: 'Cited, confidence-graded technical data on every film — cameras, lenses, lighting, color, sound, music, stunts, and VFX — for working camera-department pros.',
```

This is 157 characters. The `truncateForMeta` helper caps film pages at 155 but is not applied to the layout-level default. Google truncates SERP snippets at ~158 characters on desktop, so this is marginal, but trimming "music, " or shortening the audience qualifier by 2 characters eliminates the risk cleanly.

## What I'd Fix First

The highest-leverage single action is to **expand `sitemap-core.xml` and add new segment sitemaps** for the 67+ routes that are currently invisible to crawlers. The sound, music, editing, production-design, and costume-hair-makeup departments each have 3–12 routes; walkthroughs, dossiers, and decisions have live detail pages that Google cannot find without internal-link traversal. Adding these to the sitemap index costs almost no engineering time and immediately unblocks organic discovery for months of editorial work. Run that alongside patching the `Organization.logo` field (a one-line swap from `/icon-512.png` to `/apple-icon.png`) and wiring the 30+ `console.warn` catch blocks to `Sentry.captureException` — together these three changes complete the gap left by the excellent May–June SEO push and restore the codebase to full compliance with its own conventions.
